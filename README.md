# Bazaarche · فروشگاه اینترنتی با Yii 1.1

پروژه فروشگاه فارسی و راست‌به‌چپ بر پایه **Yii 1.1.32**. معماری آن بر اساس MVC، `CActiveRecord`، `CActiveForm`، `CHtml`، `CGridView` و `CLinkPager` طراحی شده است. منطق کسب‌وکار و سبد خرید به‌جای اتکا به افزونه‌های رهاشده، در کامپوننت‌های کوچک قابل نگهداری قرار دارد.

کد برنامه، قالب‌ها، ابزار نصب و تصاویر نمونه در مخزن هستند. وابستگی Yii با `composer install` نصب می‌شود؛ دیتابیس، نشست‌ها و آپلودهای محلی همراه مخزن منتشر نمی‌شوند.

## ارتقای جدید

رابط جدید با فونت محلی وزیر، مدیامنجر مشترک Ajax و درگ‌ودراپ، تصاویر WebP چنداندازه، ویرایشگر Markdown، رزرو زمان‌دار سفارش، کد تخفیف، تنظیمات واحد پول و گزارش مالی/انبار اضافه شده‌اند. راهنمای کامل در [FEATURES.md](FEATURES.md) و نتایج تست در [QA.md](QA.md) است.

## قابلیت‌ها

- **فرانت‌اند:** صفحه اصلی، محصولات منتخب، کاتالوگ، دسته‌بندی، جستجو، مرتب‌سازی، جزئیات کالا، گالری تصاویر، مشخصات فنی و تگ‌ها.
- **سبد خرید و سفارش:** افزودن کالا، ویرایش تعداد، ثبت اطلاعات مشتری و سفارش، کسر اتمی موجودی، صفحه تأیید، پنل مشاهده و تغییر وضعیت سفارش، رزرو زمان‌دار و بازگشت موجودی در لغو/انقضا/مرجوعی.
- **مدیریت:** احراز هویت مدیر، داشبورد با آمار محصولات/مطالب/سفارش‌ها، CRUD محصولات، دسته‌بندی‌ها، تگ‌ها و نوشته‌های بلاگ، مدیریت سفارش‌ها.
- **اطلاعات محصول:** SKU، قیمت، موجودی، تصاویر چندگانه، توضیحات، جدول مشخصات فنی، جدول متادیتای دلخواه، عنوان SEO و توضیح متا.
- **بلاگ:** تصویر شاخص، وضعیت پیش‌نویس/انتشار، تگ‌های مشترک، عنوان و توضیحات SEO.
- **PJAX:** بارگذاری قطعه محتوای صفحه بدون لود کامل (با `fetch`, History API و هدر `X-PJAX`؛ بدون وابستگی خارجی). اولین درخواست و ربات جستجو همان HTML معمولی دریافت می‌کنند.
- **امنیت پایه:** CSRF داخلی Yii، احراز هویت مدیر، محدودکردن فایل‌ها به عکس واقعی، نام تصادفی آپلودها، کوئری‌های پارامتری و تراکنش سفارش. محتوای کاربر در قالب‌ها HTML-encode می‌شود.

## نیازمندی‌ها

- PHP 7.4 تا 8.4؛ برای PHP 8.5 به انتشار/وصله سازگارتر و بررسی رسمی Yii نیاز است.
- افزونه‌های PHP: `pdo`, یکی از `pdo_sqlite` یا `pdo_mysql`, `mbstring`, `fileinfo`, `gd` با پشتیبانی WebP و `json`.
- Composer 2؛ وب‌سرور Apache با mod_rewrite یا PHP built-in server برای توسعه.
- اگر MySQL استفاده می‌کنید، ترجیحاً MySQL 8 یا MariaDB با InnoDB و `utf8mb4`.
- دسترسی نوشتن PHP به `protected/runtime`، `public/uploads` و assetهای Yii (پوشه `public/assets`؛ در صورت نیاز برای Yii asset manager).

## نصب ساده (SQLite)

1. مخزن `https://github.com/emadgh/yii1-shop` را clone کنید و وارد آن شوید.
2. در ریشه پروژه اجرا کنید: `composer install --no-dev --prefer-dist`.
3. نام کاربری و رمز مدیر را از طریق environment تعریف کنید.

   **PowerShell در ویندوز:**

   ```powershell
   $env:SHOP_ADMIN_EMAIL = "admin@example.com"
   $env:SHOP_ADMIN_PASSWORD = Read-Host "یک رمز قوی حداقل ۱۲ کاراکتری"
   php tools/install.php
   php tools/seed.php  # اختیاری: ۶ محصول نمونه و ۲ نوشته
   php -S 127.0.0.1:8080 -t public public/router.php
   ```

   **Bash در لینوکس:**

   ```bash
   export SHOP_ADMIN_EMAIL='admin@example.com'
   read -srp 'Admin password: ' SHOP_ADMIN_PASSWORD; echo; export SHOP_ADMIN_PASSWORD
   php tools/install.php
   php tools/seed.php  # optional
   php -S 127.0.0.1:8080 -t public public/router.php
   ```

4. فروشگاه: `http://127.0.0.1:8080/`؛ مدیریت: `http://127.0.0.1:8080/login` و پس از ورود `/admin`.

اسکریپت نصب اگر مدیر از قبل وجود داشته باشد رمز او را تغییر نمی‌دهد؛ خودکار کاربر با رمز پیش‌فرض نمی‌سازد.

## راه‌اندازی در MySQL / cPanel

1. یک دیتابیس MySQL و کاربر با دسترسی مناسب بسازید؛ پوشه **`public/` را به‌عنوان DocumentRoot تنظیم کنید**. فایل‌های `protected` و `vendor` نباید مستقیماً از وب قابل دسترسی باشند.
2. در محیط اجرای PHP متغیرهای زیر را تعریف کنید یا به‌جای آن‌ها یک فایل `protected/config/local.php` بسازید (نمونه در `local.example.php`):

   ```text
   SHOP_DSN=mysql:host=127.0.0.1;dbname=yii_store;charset=utf8mb4
   SHOP_DB_USER=yii_user
   SHOP_DB_PASSWORD=YOUR_DB_PASSWORD
   SHOP_ADMIN_EMAIL=admin@example.com
   SHOP_ADMIN_PASSWORD=YOUR_LONG_ADMIN_PASSWORD
   ```

3. در حالت استفاده از environment variables، `php tools/install.php` را اجرا کنید. این دستور خودش اسکیما را از `database/mysql.sql` نصب می‌کند. در صورت محدودبودن CLI، می‌توانید `database/mysql.sql` را در phpMyAdmin ایمپورت کنید، سپس با `php tools/install.php` کاربر مدیر را ایجاد کنید.
4. فایل `.htaccess` داخل `public/` روت‌ها را به `index.php` هدایت می‌کند. در Nginx نیز rewrite به `public/index.php` لازم است.
5. در هاست‌های اشتراکی که DocumentRoot قابل تغییر نیست، فایل‌های پروژه را بیرون از `public_html` بگذارید و فقط **محتوای `public/`** را به `public_html` منتقل کنید. در این حالت باید مسیر ریشه در `index.php` و مسیر کانفیگ با ساختار نصب تطبیق داده شود؛ توصیه اصلی همان DocumentRoot روی `public` است.

## پوشه‌ها

```text
yii1-store/
├─ composer.json
├─ public/
│  ├─ index.php, router.php, .htaccess
│  ├─ assets/css/app.css, assets/js/pjax.js
│  └─ uploads/products/, uploads/blog/
├─ protected/
│  ├─ config/main.php, local.example.php
│  ├─ components/       # Slug, UploadService, StoreCart, auth, controllers
│  ├─ controllers/      # Storefront and admin actions
│  ├─ models/           # CActiveRecord + CheckoutForm
│  ├─ views/            # RTL storefront and dashboard
│  └─ runtime/
├─ database/sqlite.sql, database/mysql.sql
└─ tools/install.php, tools/seed.php
```

## نحوه استفاده

- در `/login` وارد شوید. از صفحه مدیریت، ابتدا دسته‌بندی‌ها را بسازید، سپس در «محصول جدید» SKU، قیمت و موجودی را وارد کنید.
- برای مشخصات فنی و Metadata از جدول ردیف‌های نام و مقدار و دکمه افزودن/حذف استفاده کنید. مشخصات فنی در صفحه کالا به‌صورت جدول و متادیتا به‌شکل لیست ساختاریافته قابل مشاهده است.
- برای SEO از دو فیلد مستقل **عنوان SEO** و **توضیح متا** استفاده کنید. اسلاگ برای URL باید لاتین و خط‌تیره‌دار باشد؛ اگر خالی باشد، Yii یک شناسه ASCII یکتا تولید می‌کند.
- برای تصاویر از کتابخانه رسانه مشترک انتخاب کنید یا با کشیدن‌ورهاکردن آپلود کنید. JPG، PNG و WebP به سه اندازه WebP تبدیل می‌شوند. نخستین انتخاب تصویر اصلی است؛ پاک‌کردن انتخاب، فایل مشترک را از کتابخانه حذف نمی‌کند.
- سفارش با وضعیت `pending` ساخته می‌شود. مدیر در «سفارش‌ها» می‌تواند آن را تأیید، ارسال، تکمیل یا لغو کند. لغو موجودی را برمی‌گرداند و نهایی است.

## وضعیت پروژه و کارهای لازم پیش از انتشار عمومی

**این بسته یک فروشگاه عملیاتی پایه / MVP است، نه فروشگاه دارای پرداخت واقعی یا گواهی آمادگی تولید.** امکان ثبت سفارش وجود دارد، ولی پرداخت آنلاین، هزینه حمل، مالیات، سیستم پیامکی/ایمیلی، کاربران مشتری، احراز هویت دومرحله‌ای، بازیابی رمز، سیستم ضدربات/محدودسازی تلاش ورود، سطوح دسترسی پیشرفته، و ادغام لجستیک پیاده نشده‌اند. برای فعال‌سازی پرداخت، باید ماژول مستقل درگاه و callback امن با تأیید سروری تراکنش اضافه شود.

- فقط تحت HTTPS و با پیکربندی درست دسترسی پوشه‌ها روی اینترنت قرار دهید؛ در Nginx اجرای PHP داخل `/uploads` را جداگانه مسدود کنید.
- نسخه Yii را در محدوده وصله‌های رسمی به‌روز نگه دارید. **Yii 1.1 در حالت نگهداری است و تضمین وصله امنیتی آن طبق وب‌سایت رسمی فقط تا ۳۱ دسامبر ۲۰۲۶ اعلام شده است.** مهاجرت بلندمدت را برنامه‌ریزی کنید.
- نسخه پشتیبان منظم پایگاه داده و پوشه آپلود، مانیتورینگ خطا، CSP، کش، تست نفوذ و تست یکپارچه سفارش را پیش از لانچ واقعی آماده کنید.
- تصاویر آپلودی در سرور با GD به WebP بازرمزگذاری می‌شوند و سه اندازه دارند؛ فایل اصلی نگهداری نمی‌شود.
- CSS، JS و فونت برنامه محلی‌اند. اتصال Matomo فقط با واردکردن آدرس و شناسه سایت در تنظیمات فعال می‌شود. آمار داخلی به سرویس بیرونی نیاز ندارد.

## بررسی کد

فایل‌های PHP با `php -l` و `public/assets/js/pjax.js` با `node --check` قابل بررسی هستند. خود اجرای یکپارچه نیازمند نصب `vendor/` و درایور PDO مناسب است.


## مدیریت قالب و محتوای صفحه اصلی

از پنل مدیریت به **مدیریت قالب‌ها ← شخصی‌سازی** بروید. برای ساخت اسلایدر منتخب ابتدا کالکشن را بسازید، سپس ویجت «محصولات کالکشن» را در قالب اضافه کنید. مدل نمایش صفحه و کارت محصول را در قالب یا فرم هر محصول انتخاب کنید. منوها، دسته‌های درختی، حالت کاتالوگ و آمار بازدید از بخش‌های مستقل مدیریت در دسترس‌اند. جزئیات در [FEATURES.md](FEATURES.md) است.

برای ارتقای نصب موجود:

```sh
php tools/upgrade.php
php tools/seed-cms.php  # optional: bundled sample artwork and collection, once
```

برای آزادشدن رزروها بدون بازدید سایت، پردازشگر را هم فعال نگه دارید:

```sh
php tools/reservations.php --watch
```

در ویندوز `./start-local.ps1` وب‌سرور و پردازشگر رزرو را با هم اجرا می‌کند. PHP از PATH یا `SHOP_PHP_BINARY` خوانده می‌شود؛ امکان `-PhpBinary` و `-Port` هم وجود دارد. در سرور واقعی، worker را با supervisor یا اجرای دوره‌ای `php tools/reservations.php` مدیریت کنید.

## آزمون‌ها

پس از نصب و seed، روی SQLite:

```sh
php tools/verify-commerce.php
php tools/verify-cms.php
php tools/verify-admin-tables.php
npm install
npx playwright install chromium
npm run test:race
npm run test:browser
```

آزمون مرورگر یک وب‌سرور موقت و کپی دیتابیس می‌سازد و داده‌های اصلی را ویرایش نمی‌کند. برای حساب آزمایشی نصب خودتان، `SHOP_TEST_EMAIL` و `SHOP_TEST_PASSWORD` را تنظیم کنید. پیش‌فرض این ابزارها فقط حساب دموی `demo@bazaarche.test` با رمز `BazaarcheTest123!` است؛ نصب‌کننده چنین حسابی را خودکار نمی‌سازد. `SHOP_PHP_BINARY` و `SHOP_CHROME_BINARY` مسیرهای اختیاری ابزارها هستند. تست‌های PHP و هم‌زمانی هم دیتابیس جداگانه دارند. گزارش اعتبارسنجی در [QA.md](QA.md) است.
